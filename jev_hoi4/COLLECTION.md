# Parallel collection with Jev in the loop

Status as of 2026-09-24 12:15. All numbers below were measured in this VM (12 cores, 16 GB, VMware SVGA).

## Layout

```
jevai.collector  (1 process)                        jevai.jevd  (1 process, CPU model)
 slot u1: hoi4user      ─ game g05 (Jev) ─┐           reads each instance's newest history_dump month
 slot u2: runs/inst/u2  ─ game g06 (vanilla)│  .jev    → state text per country (examples.state_text)
   launch -ogl -dump_history -continuelastsave  ├──────→  → Jev: "Which strategic posture ... next 6 months?" (6 options)
   observe / random_seed / norender / nogui / 5  │        → eps-greedy pick, log to runs/games/<run>/actions.jsonl
   watch: end year / crash / stall               │        → jev_apply.txt + console "run jev_apply.txt"
   archive history_dump → runs/games/<run>      ─┘            → mod: jev_set_posture_k (undo old, apply new, log JEV|ACT)
```

- **Renderer `-ogl`.** D3D11 crashed in d3d11.dll whenever a second instance loaded, and once took down the desktop.
- **No menu clicks.** Each userdir has a `continue_game.json` pointing at the start save; `-continuelastsave` loads it directly.
- **Two slots.** Each instance uses ~5.6 GB; three will not fit in 16 GB. Launches are staggered by 30 s.
- **One keyboard.** Console input needs a foreground window, so `console.ps1` takes a global mutex and refuses to type (exit 2) if it can't get focus. The collector and jevd never type into the wrong window.
- **Game queue** (`--jev alt`): even-numbered games have Jev in the loop; the others are pure vanilla controls. Saves alternate between historical and non-historical focuses, and every game gets a different `random_seed`.

## What Jev controls (v1)

Six targetless postures, generated by `jevai/gen_mod.py` into `mod/jevai_probe/common/scripted_effects/jev_postures.txt`:
1. defensive buildup, 2. industrial expansion, 3. armored offensive, 4. air power, 5. naval power, 6. total war economy.

Each posture is a bundle of `add_ai_strategy` entries (role_ratio, unit_ratio, equipment_production_factor, factory ratios, force concentration). Every entry has an exact inverse, so a switch undoes the old posture before applying the new one. The active posture is stored in the country variable `jev_posture`.

Which countries Jev controls:
- Per game, each country with at least 20 factories is Jev-controlled with probability 0.5 (`control.json`). The rest stay vanilla, as a within-game control group.
- Each controlled country is re-decided every 2 months, staggered. That keeps inference to about 7–12 s per game month, against roughly 40 s of game time per month.
- eps = 0.3: 30% of decisions are uniform random. Each action records its propensity and Jev's full distribution, so outcomes can be read causally and reweighted.

Targeted diplomacy (prepare_for_war / antagonize against a specific tag) is not wired up yet. The scope hand-off that the effect relies on is unverified in-game.

## Data produced

- `runs/games/<run>/history_dump/*.txt`: one JSON per month (map PNGs are dropped).
- `runs/games/<run>/actions.jsonl`: every Jev decision, with state, distribution, action, explore flag and propensity.
- `python -m jevai.build_dataset`:
  - records → forecast questions (3/6/12-month horizons);
  - actions attached to records → action-value questions (`act_grow`, `act_ok`, `act_gain`);
  - split by whole game (`g..4` → test, `g..3` → val).

Current dataset (games g01–g04, all vanilla): **74,224 states / 393,005 questions** (train 58,860 / val 8,224 / test 7,140). That is already past the ~10k target for forecast data. Action-value data only starts with g05.

## Known limits

- Stock Jev knows nothing about HOI4. Its posture choice is nearly the same for every country (mostly "total war economy", p ≈ 0.3–0.38), so today the policy is close to "exploration plus one default". That is expected: the point of this phase is to collect randomized action→outcome data for training.
- Fresh 1936 starts crash around June 1936, so every game starts from the 1936-06-01 save.
- The mod's `JEV|ACT` log confirms each posture was applied. Whether a posture measurably changes AI behaviour (production mix, unit ratio) still has to be checked from the dumps once g05 finishes.
